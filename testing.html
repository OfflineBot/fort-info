4 · Testing

4.1 Test-Pyramide

Im Kurs wird die klassische Pyramide unterrichtet:

  1. Unit-Tests — testen eine einzelne Klasse / Methode isoliert. Schnell, viele.
  2. Integrationstests — testen das Zusammenspiel mehrerer Komponenten (z.B. Controller + Service + Repository). Mittlere Anzahl.
  3. Systemtests — testen die ganze Anwendung end-to-end (HTTP rein, JSON raus, evtl. DB). Wenige, langsam.

Faustregel: wenig Systemtests, viele Unit-Tests, mittel viele Integrationstests.

4.2 JUnit 5 Basics

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class MovieServiceTest {

    private MovieService service;

    @BeforeEach
    void setUp() { service = new MovieServiceImpl(...); }

    @Test
    @DisplayName("findAll liefert alle Filme")
    void findAll() {
        var movies = service.getAllMovies();
        assertEquals(2, movies.size());
    }

    @Test
    void findByIdWirftWennNichtVorhanden() {
        assertThrows(NoSuchElementException.class,
            () -> service.getMovieById(999L));
    }
}

Lifecycle: @BeforeAll (static), @BeforeEach, @AfterEach, @AfterAll (static). Außerdem nützlich: @DisplayName, @Disabled, @Tag.

4.3 Test Doubles & Mockito

Test Double = Sammelbegriff für Ersatzobjekte. Im Spring-Kontext:

  • Dummy — wird übergeben, aber nie genutzt.
  • Stub — gibt vordefinierte Antworten zurück.
  • Mock — wie Stub, plus Verifikation der Aufrufe.
  • Spy — echtes Objekt, einzelne Methoden überschrieben.
  • Fake — eigene, vereinfachte Implementierung (z.B. In-Memory-Repo).
import static org.mockito.Mockito.*;

@Test
void mockBeispiel() {
    MovieService mock = mock(MovieService.class);
    when(mock.getMovieById(1L)).thenReturn(new MovieDTO(...));

    var result = mock.getMovieById(1L);
    assertNotNull(result);

    verify(mock).getMovieById(1L);
    verify(mock, never()).getAllMovies();
}

4.4 MockMvc & @WebMvcTest

@WebMvcTest(controllers = X.class) startet nur den MVC-Layer (kein voller Kontext, keine DB) und gibt dir MockMvc zum Aufruf der Endpoints. Service-Beans werden mit @MockBean gemockt.

@WebMvcTest(controllers = MovieControllerImpl.class)
public class MovieControllerImplTest {

    @MockBean    private MovieService movieService;
    @Autowired   private MockMvc      mockMvc;
    @Autowired   private ObjectMapper objectMapper;

    private MovieDTO movie_1;

    @BeforeEach
    public void setUp() {
        movie_1 = new MovieDTO(1L, "Interstellar", 2.49, /* ... */ );
    }

    @Test
    public void shouldReturnMovieById() throws Exception {
        when(movieService.getMovieById(1L)).thenReturn(movie_1);

        mockMvc.perform(get("/api/v1/movies/1"))
               .andExpect(status().isOk())
               .andExpect(jsonPath("$.title", is("Interstellar")));

        verify(movieService).getMovieById(1L);
    }

    @Test
    public void shouldReturn404WhenIdUnknown() throws Exception {
        when(movieService.getMovieById(anyLong()))
            .thenThrow(new NoSuchElementException("not found"));

        mockMvc.perform(get("/api/v1/movies/20"))
               .andExpect(status().isNotFound());
    }
}

4.5 JsonPath

Mit jsonPath("$.feld", matcher) prüfst du gezielt einzelne Felder im JSON-Response.

JsonPathBedeutung
$Wurzel
$.titleFeld title
$[0]erstes Array-Element
$.*alle direkten Kinder
$.awards[0].academyverschachtelt

Beliebte Hamcrest-Matcher (statisch importiert über org.hamcrest.Matchers.*):

.andExpect(jsonPath("$.*", hasSize(2)))
.andExpect(jsonPath("$[0].title", is("Interstellar")))
.andExpect(jsonPath("$.castIds", containsInAnyOrder(1, 2, 4)));

⚙ Aufgabe 6 — Controller-Tests

Aufgabenstellung

Schreibe einen MovieControllerImplTest, der mit @WebMvcTest + MockMvc alle Endpoints der MovieController-API abdeckt:

  1. GET-Liste: 2 Filme, prüfe Größe und alle Felder von Film 1.
  2. GET-by-ID: existierende ID → 200 mit Film-Daten.
  3. GET-by-ID: unbekannte ID → 404.
  4. POST: erfolgreich → 201.
  5. POST mit ungültigem Payload (z.B. trailerUrl=null) → 400, Service wird nicht aufgerufen.
  6. PUT: erfolgreich → 200; PUT mit unbekannter ID → 404; PUT mit ungültigem Payload → 400.
  7. DELETE: erfolgreich → 200; DELETE mit unbekannter ID → 404.

Verwende @MockBean für den MovieService und prüfe per verify(), dass der Service korrekt (oder eben gar nicht) aufgerufen wurde.

Hier die wichtigsten Tests aus der Lösung; Setup mit zwei Test-Filmen (Interstellar, The Dark Knight):

@Test
public void shouldSucessfullyReturnAllMovies() throws Exception {
    when(movieService.getAllMovies()).thenReturn(movieList);

    mockMvc.perform(get("/api/v1/movies"))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.*", hasSize(2)))
        .andExpect(jsonPath("$[0].id",       is(movie_1.getId().intValue())))
        .andExpect(jsonPath("$[0].title",    is(movie_1.getTitle())))
        .andExpect(jsonPath("$[0].awards[0].celebrationYear",
                             is(movie_1.getAwards().get(0).getCelebrationYear())));

    verify(movieService).getAllMovies();
}

@Test
public void shouldFailGetMovie() throws Exception {
    when(movieService.getMovieById(anyLong()))
        .thenThrow(new NoSuchElementException("No movie found for id"));

    mockMvc.perform(get("/api/v1/movies/20"))
           .andExpect(status().isNotFound());

    verify(movieService).getMovieById(20L);
}

@Test
public void shouldFailAddNewMovieDueToConstraintViolation() throws Exception {
    // kein when() — Constraint Violation passiert VOR dem Controller!
    movie_1.setTrailerUrl(null);

    mockMvc.perform(post("/api/v1/movies")
            .contentType(MediaType.APPLICATION_JSON)
            .content(objectMapper.writeValueAsString(movie_1)))
        .andExpect(status().isBadRequest());

    verify(movieService, never()).addMovie(any());
}

Wichtige Lehre aus der Lösung: bei Validation-Fehlern (@Valid) wird die Service-Methode nicht aufgerufen — deshalb auch kein when(), dafür ein verify(..., never()).

🧠 Verständnis-Checks

Klick auf „Antwort anzeigen" — schnelles Selbstabfragen ohne Scrollen.

Was sagt die Best-Practice-Konvention im Kurs zur Benennung von Testklassen?

Antwort anzeigen
Testklasse beginnt mit dem Namen der zu testenden Klasse und endet auf Test: z.B. MovieControllerImplTest, AwardControllerImplTest.

Wie sollen Testmethoden laut Folie heißen?

Antwort anzeigen
Mit Präfix should + dem zu testenden Verhalten — sowohl Erfolgs- als auch Fehlerfall: shouldSuccessfullyLogin, shouldNotLoginBecauseWrongPassword, shouldNotLoginBecauseEmptyPassword.

Wo liegt der Test-Ordner und wie soll seine Struktur aussehen?

Antwort anzeigen
src/test/. Die Package-Struktur muss identisch zu src/main/ sein — sonst funktioniert die DI von Spring beim Laden der Test-Beans nicht zuverlässig.

Erkläre die drei Test-Arten der Pyramide kurz.

Antwort anzeigen
Unit-Test: einzelne Methode/Klasse isoliert. Integrationstest: Zusammenspiel mehrerer Komponenten (z.B. Controller→Service→Repo). Systemtest: gesamte Anwendung inkl. nicht-funktionaler Anforderungen, möglichst nahe am Produktivsystem.

Was ist die zentrale Herausforderung bei Unit-Tests in Spring, die Test-Doubles lösen?

Antwort anzeigen
Klassen haben Abhängigkeiten zu anderen (Controller→Service→Repo). Um eine Methode isoliert zu testen, ersetzt man die Abhängigkeit durch ein Test-Double — die echte Implementierung wird nicht aufgerufen.

Erkläre Fake vs. Mock vs. Stub gemäß Kurs.

Antwort anzeigen
Fake: eigenständig geschriebene Alternativ-Implementierung mit reduzierter Komplexität (aufwändig). Mock: automatisch generiert, Standard-Rückgaben, Fokus auf Aufruf-Verhalten. Stub: semi-automatisch, angepasstes Antwortverhalten, Fokus auf Zustand/Ergebnis.

Banking-Beispiel: was prüft ein Stub vs. ein Mock bei einer Überweisung?

Antwort anzeigen
Stub bildet das Konto-Antwortverhalten nach (Stand 100€ → Transaktion → Stand 80€) und prüft den Endzustand. Mock prüft nur, ob der Transaktionsbefehl korrekt an den Bankserver geschickt wurde — nicht den Kontostand.

Welche Annotation verwandelt eine Klasse im Spring-Test in einen Mock?

Antwort anzeigen
@MockBean auf dem Feld. Spring ersetzt damit die echte Bean im Test-Kontext durch eine Mockito-Mock-Implementierung — alle Methoden geben Defaults zurück, bis du sie mit when().thenReturn() stubbst.

Was startet @WebMvcTest(controllers = X.class)?

Antwort anzeigen
Nur den MVC-Layer (Controller + ControllerAdvice + Filters) für die genannte Klasse. Kein Service-, Repository- oder DB-Bean wird geladen — alle Service-Abhängigkeiten musst du per @MockBean mocken. Ergebnis: schnelle Tests.

Was ersetzt MockMvc gegenüber Postman?

Antwort anzeigen
Postman ist manuelles HTTP-Aufrufen. MockMvc simuliert HTTP-Requests im Test ohne echten Server zu starten — du kannst URL, Methode, Header, Body steuern und Status, Headers, JSON-Body assertieren.

Schreibe ein Stub für: movieService.getMovieById(1L) soll movie_1 zurückgeben.

Antwort anzeigen
when(movieService.getMovieById(1L)).thenReturn(movie_1);

Was prüft verify(movieService, never()).addMovie(any()) und wann ist das relevant?

Antwort anzeigen
Es prüft, dass addMovie nicht aufgerufen wurde. Relevant z.B. bei Constraint-Violation-Tests: wenn der Validator vor dem Controller schlägt, darf der Service gar nicht erst angefasst werden.

Warum hat dieser Test kein when()?

movie_1.setTrailerUrl(null);
mockMvc.perform(post("/api/v1/movies")
  .contentType(APPLICATION_JSON)
  .content(objectMapper.writeValueAsString(movie_1)))
  .andExpect(status().isBadRequest());

Antwort anzeigen
Weil die @Valid-Constraint-Violation vor dem Controller geworfen wird — der Service wird nicht aufgerufen, also gibt es nichts zu stubben. Stattdessen prüft man am Ende per verify(service, never())….

JsonPath: wie liest du das academy-Feld des ersten Awards des ersten Movies?

Antwort anzeigen
$[0].awards[0].academy. Bei einer einzelnen Movie-Antwort entsprechend $.awards[0].academy.

Welche zwei JUnit-Lifecycle-Annotationen werden im Kurs für Setup empfohlen, und wofür?

Antwort anzeigen
@BeforeAll (statisch, einmal pro Testklasse) für teures Setup; @BeforeEach (vor jeder Testmethode) für frische Test-Objekte, damit kein Test den anderen beeinflusst.
