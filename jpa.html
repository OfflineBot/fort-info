📄 Folien-PDF anzeigen / herunterladen 2-JPA-Grundlagen.pdf

🎯 TL;DR — was du wirklich wissen musst

  • JPA = Spec, Hibernate = Implementierung, Spring Data JPA = Repository-Schicht obendrauf.
  • Entity: @Entity + @Id + @GeneratedValue. Lombok-Annotationen sparen Boilerplate.
  • Beziehungen: @OneToOne, @OneToMany, @ManyToOne, @ManyToMany. Inverse Seite = mappedBy="feldname".
  • Repository: extends JpaRepository<T, ID> + Derived Queries (findByXContaining) oder @Query mit JPQL.
  • JPQL ≠ SQL: auf Klassennamen + Feldnamen, nicht Tabellen + Spalten. SELECT m FROM Movie m WHERE m.title = :t.
  • @Transactional: bündelt DB-Calls. Pflicht für Lazy-Loading-Auflösung. Nur von außerhalb der Bean aufrufbar.

⚠ Typische Fehler / Klausur-Stolperfallen

Die Punkte, an denen die meisten in der Klausur Federn lassen.

⚠ @OneToMany ohne mappedBy bei bidirektionaler Beziehung
JPA legt dann zwei Join-Tabellen an statt einer. Auf der inversen Seite immer mappedBy = "feldname" setzen — Wert ist der Java-Feldname der owning side.
⚠ cascade = CascadeType.ALL blind setzen
Beim delete(movie) löschst du dann auch den Director — andere Filme verlieren ihre Beziehung. Bewusst pro Beziehung wählen: oft nur PERSIST + MERGE.
⚠ JPQL mit Tabellennamen statt Klassennamen
SELECT * FROM movies ist SQL, nicht JPQL. Korrekt: SELECT m FROM Movie m — Klassenname + Alias. Felder als m.title, nicht title_column.
⚠ Lazy-Beziehung außerhalb Transaktion zugreifen
LazyInitializationException bei der Serialisierung. Lösung: Service-Methode mit @Transactional annotieren — solange offen ist, kann Hibernate nachladen.
⚠ @Transactional intern aufrufen
Methode A in derselben Bean ruft Methode B mit @Transactional auf — die Annotation greift NICHT, weil Spring sie nur bei externen Aufrufen über den Proxy abfängt.

2.1 ORM & JPA-Grundlagen

ORM (Object-Relational Mapping) bildet Java-Objekte auf relationale Tabellen ab. JPA (Jakarta Persistence API) ist die Java-Spezifikation dafür; Hibernate ist die in Spring Boot mitgelieferte Standard-Implementierung. Spring Data JPA packt eine Repository-Schicht obendrauf, die viele CRUD-Operationen ohne eine Zeile SQL bereitstellt.

Begriffe

BegriffBedeutung
EntityJava-Klasse, die einer Tabelle entspricht (@Entity)
EntityManagerverwaltet Entity-Lebenszyklus (intern in Spring Data)
Persistence ContextCache der "verwalteten" Entities während einer Transaktion
RepositoryInterface mit CRUD- & Such-Methoden (JpaRepository)
JPQLObject-Query-Sprache — wie SQL, aber auf Entities statt Tabellen

2.2 Entity-Mapping

Eine Entity-Klasse braucht @Entity und ein @Id-Feld. Im Kurs werden zur Reduktion von Boilerplate Lombok-Annotationen genutzt.

package de.dhbw.ravensburg.wp.mymoviedatabase.model;

import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;
import jakarta.persistence.*;
import java.time.LocalDate;
import java.util.List;

@Getter
@Setter
@NoArgsConstructor
@Entity
public class Movie {

    @Id
    @GeneratedValue
    private long id;

    private String title;
    private double duration;
    private LocalDate premiereDate;
    private String description;
    private String trailerUrl;
    private String coverImgUrl;
    private double imdbRating;

    @ManyToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "director_id", nullable = true)
    private Director director;

    @ManyToMany(cascade = CascadeType.ALL)
    @JoinTable(name = "movie_moviecast",
        joinColumns        = { @JoinColumn(name = "movie_id", referencedColumnName = "id") },
        inverseJoinColumns = { @JoinColumn(name = "cast_id",  referencedColumnName = "id") })
    private List<MovieCast> involvedMovieCast;

    @OneToOne(mappedBy = "movie", cascade = CascadeType.ALL)
    private Soundtrack soundtrack;
}

Wichtige Annotationen:

  • @Entity — Klasse wird einer Tabelle zugeordnet (Tabellenname = Klassenname).
  • @Id — Primärschlüssel-Feld.
  • @GeneratedValue — DB generiert die ID (Auto-Increment).
  • @Column — Spalten-Konfiguration (Name, nullable, length, …).
  • @JoinColumn / @JoinTable — Konfiguration der FK-Spalten bzw. Verknüpfungstabellen.

2.3 JpaRepository & Derived Queries

Ein JpaRepository stellt CRUD-Methoden zur Verfügung (save, findById, findAll, deleteById, …). Zusätzliche Methoden lassen sich allein durch Methodennamen definieren — Spring leitet daraus die Query ab.

@Repository
public interface MovieRepository extends JpaRepository<Movie, Long> {
    List<Movie> findByTitleContaining(String substring);
    List<Movie> findByImdbRatingGreaterThan(double rating);
    List<Movie> findByPremiereDateAfter(LocalDate reference);
}

Derived-Query Schlüsselwörter (Auswahl)

KeywordSQL-Pendant
findBy{Feld}WHERE feld = ?
...ContainingLIKE '%?%'
...StartingWith / ...EndingWithLIKE '?%' / LIKE '%?'
...GreaterThan / ...LessThan> / <
...After / ...BeforeDatumvergleich
...BetweenBETWEEN ? AND ?
...InIN (?, ?, ...)
...And... / ...Or...Logik-Operator
...OrderBy{Feld}{Asc|Desc}ORDER BY feld

2.4 @Query (JPQL)

Wenn die Methodennamen-Konvention nicht reicht, schreibt man die Query selbst — in JPQL (auf Entities, nicht Tabellen) oder als native SQL.

@Query("SELECT m FROM Movie m WHERE m.title = :param1")
List<Movie> findAllMoviesByTitle(@Param("param1") String title);

@Query("SELECT m FROM Movie m WHERE m.duration < 2.3 AND m.imdbRating > 7.0")
List<Movie> findAllShortMoviesWithGoodImdbRating();

Achtung: in JPQL referenzierst du Klassennamen (Movie) und Feldnamen (m.title), nicht Tabellen- oder Spaltennamen.

2.5 Beziehungen & Cascade

AnnotationKardinalitätBeispiel
@OneToOne1:1Movie ↔ Soundtrack
@OneToMany1:nMovie → Awards
@ManyToOnen:1Movie → Director
@ManyToManyn:mMovie ↔ MovieCast

CascadeType

Steuert, welche Operationen vom Parent auf das Child weitergereicht werden:

  • PERSIST — save(parent) speichert auch das Child
  • MERGE — Update wird durchgereicht
  • REMOVE — Löschen wird durchgereicht
  • ALL — alle vier (PERSIST + MERGE + REMOVE + REFRESH + DETACH)

Im Kurs steht überall cascade = CascadeType.ALL — pragmatisch für Übungen, in Produktion bewusster wählen (sonst löscht ein delete(movie) den ganzen Director mit, was selten gewollt ist).

mappedBy — wer "besitzt" die Beziehung

In bidirektionalen Beziehungen gibt es eine owning side (mit @JoinColumn) und eine inverse side (mit mappedBy = "feldname"). Beispiel Award ↔ Movie:

@Entity
public class Award {
    @ManyToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "movie_id")     // owning side
    private Movie movie;
}

// Movie wäre die inverse side (würde sie eine Liste der Awards halten):
// @OneToMany(mappedBy = "movie")
// private List<Award> awards;

2.6 Transaktionen

Spring verwaltet Transaktionen deklarativ über @Transactional. Standardmäßig sind JpaRepository-Methoden bereits in eine Transaktion gewrappt. Auf Service-Ebene macht man:

@Service
public class MovieServiceImpl implements MovieService {

    private final MovieRepository repo;
    public MovieServiceImpl(MovieRepository repo) { this.repo = repo; }

    @Transactional   // alle DB-Aufrufe in dieser Methode sind eine Einheit
    public Movie addWithAward(Movie m, Award a) {
        m.getAwards().add(a);
        return repo.save(m);
    }
}

ACID-Eigenschaften: Atomicity, Consistency, Isolation, Durability.

⚙ Aufgabe 3 — Award + 1:n

Aufgabenstellung
📦 Starter-ZIP ✅ Lösungs-ZIP

Erweitere das Datenmodell um die Entity Award mit den Feldern academy, category, yearAwarded. Verknüpfe sie mit Movie (n:1, ein Film kann mehrere Awards haben). Schreibe eine Repository-Methode, die alle Awards eines Films per Movie-ID findet.

@Getter @Setter @NoArgsConstructor
@Entity
public class Award {
    @Id @GeneratedValue
    private Long id;

    private String academy;
    private String category;
    private int yearAwarded;

    @ManyToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "movie_id")
    private Movie movie;

    public Award(String academy, String category, int yearAwarded) {
        this.academy     = academy;
        this.category    = category;
        this.yearAwarded = yearAwarded;
    }
}

@Repository
public interface AwardRepository extends JpaRepository<Award, Long> {
    List<Award> findByMovie_Id(Long movieId);
}

Das Underscore _ in findByMovie_Id sagt Spring Data: navigiere in der Beziehung movie auf das Feld id.

⚙ Weitere Aufgabe 1 — Director-Entity bidirektional (komplett)

Aufgabenstellung

Erweitere das Datenmodell um eine vollständige Director ↔ Movie-Beziehung in beide Richtungen, analog zu wie Award ↔ Movie in Aufgabe 3 modelliert ist.

  1. Director-Entity mit id, name, geburtsjahr, nationality.
  2. In Director: @OneToMany(mappedBy = "director") List<Movie> filmography als inverse Seite.
  3. Movie bleibt owning side (war schon in Aufgabe 3: @ManyToOne + @JoinColumn).
  4. DirectorRepository mit drei Methoden: findByNameStartingWith(prefix), findByNationality(n), @Query über Path-Navigation für „alle Directors mit mind. einem Film > Rating X".
  5. DirectorService + DirectorServiceImpl analog zum bestehenden Award-Pattern.
  6. In ManualTestBean testen: lege „Christopher Nolan" an, verknüpfe mit „Interstellar", lade Director per ID, logge Filmografie-Größe.
// Director.java
package de.dhbw.ravensburg.wp.mymoviedatabase.model;

import jakarta.persistence.*;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;
import java.util.ArrayList;
import java.util.List;

@Getter @Setter @NoArgsConstructor
@Entity
public class Director {

    @Id @GeneratedValue
    private Long id;

    private String name;
    private int geburtsjahr;
    private String nationality;

    @OneToMany(mappedBy = "director")
    private List<Movie> filmography = new ArrayList<>();

    public Director(String name, int geburtsjahr, String nationality) {
        this.name = name;
        this.geburtsjahr = geburtsjahr;
        this.nationality = nationality;
    }
}
// Movie.java — bestehender Block (zur Erinnerung, schon aus Aufgabe 3)
@ManyToOne(cascade = CascadeType.ALL)
@JoinColumn(name = "director_id", nullable = true)
private Director director;
// DirectorRepository.java
package de.dhbw.ravensburg.wp.mymoviedatabase.repository;

import de.dhbw.ravensburg.wp.mymoviedatabase.model.Director;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;
import java.util.List;

@Repository
public interface DirectorRepository extends JpaRepository<Director, Long> {

    List<Director> findByNameStartingWith(String prefix);

    List<Director> findByNationality(String nationality);

    @Query("""
        SELECT DISTINCT d FROM Director d
        JOIN d.filmography m
        WHERE m.imdbRating > :minRating
    """)
    List<Director> findWithAtLeastOneTopMovie(@Param("minRating") double minRating);
}
// DirectorService.java
public interface DirectorService {
    List<Director> getAll();
    Director       getById(Long id);
    Director       add(Director d);
    Director       update(Director d);
    void           removeById(Long id);
}

// DirectorServiceImpl.java
@Service
public class DirectorServiceImpl implements DirectorService {
    private final DirectorRepository repo;
    public DirectorServiceImpl(DirectorRepository r) { this.repo = r; }

    @Override public List<Director> getAll()          { return repo.findAll(); }
    @Override public Director getById(Long id)        {
        return repo.findById(id).orElseThrow(
            () -> new NoSuchElementException("Director " + id));
    }
    @Override public Director add(Director d)         { return repo.save(d); }
    @Override public Director update(Director d)      { return repo.save(d); }
    @Override public void     removeById(Long id)     { repo.deleteById(id); }
}

Aufgabenstellung

Schreibe eine JPQL-Query, die alle Filme eines bestimmten Directors mit IMDB-Rating > X liefert, sortiert nach Premiere absteigend.

  1. Methode in MovieRepository: findByDirectorAndMinRating(String directorName, double minRating).
  2. JPQL mit JOIN auf m.director.

@Query("""
    SELECT m FROM Movie m
    WHERE m.director.name = :name
      AND m.imdbRating > :minRating
    ORDER BY m.premiereDate DESC
""")
List<Movie> findByDirectorAndMinRating(
    @Param("name") String directorName,

Als Derived Query geht das auch — Spring Data unterstützt Navigation in Beziehungen via Underscore:

⚙ Weitere Aufgabe 3 — Lazy/Eager Fetching + @Transactional

Aufgabenstellung

Die Folien behandeln Ladestrategien (FetchType) und @Transactional. Setze Folgendes um:

  1. Schalte die Beziehung Movie → MovieCast auf FetchType.LAZY.
  2. Schreibe im MovieServiceImpl eine Methode getCastOfMovie(Long id), die Movie lädt und die Cast-Liste zurückgibt.
  3. Ohne @Transactional sollte beim Zugriff auf die Cast-Liste eine LazyInitializationException fliegen — warum?
  4. Mit @Transactional über der Methode funktioniert es. Erkläre, warum die Annotation laut Folie mit Bedacht gesetzt werden soll.
@Entity
public class Movie {
    @ManyToMany(fetch = FetchType.LAZY, cascade = CascadeType.ALL)
    @JoinTable(name = "movie_moviecast", /* ... */)
    private List<MovieCast> involvedMovieCast;
}

@Service
public class MovieServiceImpl implements MovieService {

    private final MovieRepository repo;
    public MovieServiceImpl(MovieRepository r) { this.repo = r; }

    @Transactional   // Pflicht für LAZY-Auflösung
    public List<MovieCast> getCastOfMovie(Long id) {
        Movie m = repo.findById(id).orElseThrow();
        return m.getInvolvedMovieCast();  // Triggert die LAZY-Query
    }
}

Warum LazyInitializationException? Lazy-Loaded Beziehungen werden erst beim Zugriff geladen — dafür braucht es eine offene Datenbank-Transaktion. Ohne @Transactional ist die Session schon geschlossen, wenn der Controller die Liste serialisieren will.

Folien-Warnung: "Niemals @Transactional verwenden, wenn nicht unbedingt eine Transaktion benötigt wird" — der Transaktionskontext hat Folgen für den Programmfluss (Rollback-Verhalten, Verschachtelung, etc.). Außerdem: Transaktionen können nur von außerhalb einer Bean initiiert werden — interne Methodenaufrufe in derselben Bean umgehen die Annotation.

🧠 Verständnis-Checks

Klick auf „Antwort anzeigen" — schnelles Selbstabfragen ohne Scrollen.

Welche zwei Annotationen brauchst du minimal, damit eine Klasse zur JPA-Entity wird?

Antwort anzeigen
@Entity auf der Klasse + @Id auf einem Feld. Ohne Primary Key wirft Hibernate beim Start einen Fehler.

Was bewirkt @GeneratedValue?

Antwort anzeigen
Die DB (bzw. Hibernate) erzeugt den Wert automatisch — typischerweise via Auto-Increment oder Sequenz. Du musst die ID nie selbst setzen; sie ist nach save() verfügbar.

Bei Movie ↔ Director (ein Film hat einen Director, ein Director hat viele Filme): welche Annotation auf welcher Seite?

Antwort anzeigen
Auf Movie: @ManyToOne (viele Filme zeigen auf einen Director) mit @JoinColumn(name="director_id"). Auf Director (falls bidirektional): @OneToMany(mappedBy="director").

Was macht mappedBy?

Antwort anzeigen
Es markiert die inverse Seite einer bidirektionalen Beziehung. Der Wert ist der Feldname der owning Seite (mit der @JoinColumn). Ohne mappedBy würde JPA zwei Beziehungstabellen anlegen statt einer.

Bei cascade = CascadeType.ALL: was passiert, wenn ich einen Movie lösche, der einen Director referenziert?

Antwort anzeigen
Der Director wird mitgelöscht. Das ist im Kurs für Übungen pragmatisch, in Produktion aber meist falsch — andere Filme könnten denselben Director referenzieren. Bewusste Wahl pro Beziehung empfohlen.

Schreibe eine Derived Query, die alle Filme mit IMDB-Rating > 7 sortiert nach Premiere absteigend findet.

Antwort anzeigen
List<Movie> findByImdbRatingGreaterThanOrderByPremiereDateDesc(double rating); — Spring Data leitet die Query allein aus dem Methodennamen ab.

In @Query("SELECT m FROM Movie m WHERE m.title = :t"): ist Movie eine Tabelle oder eine Klasse?

Antwort anzeigen
Eine Klasse (Java-Entity-Name). JPQL operiert auf dem Object-Modell, nicht auf SQL-Tabellen. Felder wie m.title sind Java-Feldnamen, nicht Spaltennamen.

Was bedeutet Persistence Context?

Antwort anzeigen
Der Cache der verwalteten Entities innerhalb einer Transaktion. Solange ein Objekt im Persistence Context lebt, schreibt JPA jede Änderung beim Commit automatisch zurück — ohne dass du save() aufrufen musst.
