6 · Thymeleaf

6.1 Server-Side vs. Client-Side Rendering

Im Kurs werden drei Render-Modelle gegenübergestellt:

  1. Klassisches Server-Rendering (Thymeleaf): Server liefert die fertig zusammengebaute HTML-Seite. Schnelle initiale Anzeige, weniger Last im Browser.
  2. Single-Page-App (REST + JS-Framework): Server liefert nur Daten als JSON, der Browser baut die Seite. Entlastet den Server, lädt initial länger.
  3. Hybrid: initiale Seite vom Server, dynamische Teile per JS und REST nachgeladen.

Thymeleaf ist eine server­seitige Template-Engine, die in Spring Boot Standard ist. Templates sind valides HTML — du kannst sie auch ohne Server im Browser öffnen (Platzhaltertexte werden gerendert).

6.2 Syntax & Expressions

Templates landen unter src/main/resources/templates/, statische Assets unter src/main/resources/static/. Im Template-Tag muss der Namespace stehen:

<html xmlns:th="http://www.thymeleaf.org">

Expression-Typen

SyntaxBedeutungBeispiel
${…}Variable / OGNL${movie.title}
*{…}Selection (innerhalb th:object)*{title}
@{…}URL@{/css/bootstrap.min.css}
#{…}i18n / messages.properties#{login.title}
~{…}Fragment~{fragments/banner :: banner}

Wichtige th:-Attribute

AttributWirkung
th:textsetzt den Textinhalt
th:hrefsetzt das href-Attribut (mit Context-Path)
th:srcsetzt das src-Attribut
th:if / th:unlessbedingtes Rendering
th:eachIteration
th:object / th:fieldFormular-Binding
th:insert / th:replaceFragments einbetten

6.3 Controller + ModelAndView

Ein Thymeleaf-Controller ist ein normaler @Controller, dessen Methoden den Template-Namen (ohne .html) zurückgeben. Daten gehen über Model oder ModelAndView ins Template.

@Slf4j
@Controller
public class ThMovieControllerImpl implements ThMovieController {

    private final MovieService movieService;

    public ThMovieControllerImpl(MovieService movieService) {
        this.movieService = movieService;
    }

    @Override
    @GetMapping(value = {"/", "/index.html"})
    public ModelAndView index() {
        List<MovieDTO> movies = movieService.getAllMovies();

        ModelAndView mv = new ModelAndView("index");
        mv.addObject("data", movies);
        return mv;
    }

    @Override
    @GetMapping("/contact")
    public String contactInfo() { return "contact"; }   // → templates/contact.html

    @Override
    @GetMapping("/version")
    public String versionInfo() { return "version"; }   // → templates/version.html
}

6.4 Fragments (insert / replace)

Wiederkehrende Bestandteile (Banner, Footer, Modals) werden in Fragments ausgelagert.

<!-- templates/fragments/banner.html -->
<!doctype html>
<html xmlns:th="http://www.thymeleaf.org">
<body>
  <section th:fragment="banner">
    <h1>My Movie Database</h1>
    <p>Die beste Filmsammlung der DHBW.</p>
  </section>
</body>
</html>
<!-- templates/index.html -->
<!doctype html>
<html lang="en" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="utf-8">
    <title>My Movie Database</title>
    <link th:href="@{css/bootstrap.min.css}" rel="stylesheet">
</head>
<body>
<main role="main">
    <section th:insert="fragments/banner :: banner"></section>
    <div     th:insert="fragments/grid   :: grid"></div>
</main>

<footer th:insert="fragments/footer :: footer"></footer>

<script th:src="@{js/bootstrap.bundle.min.js}"></script>
</body>
</html>

Unterschied:

  • th:insert — packt das Fragment in den umgebenden Tag
  • th:replace — ersetzt den umgebenden Tag komplett durch das Fragment

6.5 Iteration mit th:each

<!-- fragments/grid.html — iteriert über die Movie-Liste aus dem Model -->
<div th:fragment="grid" class="container">
  <div class="row">
    <div class="col-md-4 mb-4" th:each="movie : ${data}">
      <div class="card">
        <img class="card-img-top" th:src="${movie.coverImgUrl}">
        <div class="card-body">
          <h5 class="card-title" th:text="${movie.title}">Titel</h5>
          <p   class="card-text"  th:text="${movie.description}">…</p>
          <p>IMDB: <span th:text="${movie.imdbRating}">0</span></p>
        </div>
      </div>
    </div>
  </div>
</div>

Iter-Status (zweite Variable): th:each="m, stat : ${data}" gibt stat.index, stat.count, stat.first, stat.last, stat.even, stat.odd.

⚙ Aufgabe 10 — erste Templates

Aufgabenstellung

Lege drei Templates an:

  • templates/contact.html — Kontakt-Seite
  • templates/fragments/banner.html — wiederverwendbarer Banner
  • templates/fragments/footer.html — wiederverwendbarer Footer

Im contact.html bindest du Banner und Footer per th:insert ein. Schreibe einen Controller-Endpunkt GET /contact, der das Template ausliefert.

@GetMapping("/contact")
public String contactInfo() { return "contact"; }
<!doctype html>
<html xmlns:th="http://www.thymeleaf.org">
<head><title>Kontakt</title></head>
<body>
  <section th:insert="fragments/banner :: banner"></section>
  <main>
    <h2>Kontakt</h2>
    <p>Email: kontakt@example.com</p>
  </main>
  <footer th:insert="fragments/footer :: footer"></footer>
</body>
</html>

⚙ Aufgabe 11 — Movie-Grid

Aufgabenstellung

Baue eine Startseite, die alle Filme aus der DB als Bootstrap-Card-Grid anzeigt:

  1. ThMovieControllerImpl mit Endpunkt GET /, der alle Movies aus dem MovieService ins Model packt (Key: data) und das Template index rendert.
  2. fragments/grid.html mit Fragment grid, das per th:each über ${data} iteriert und je Movie eine Card rendert (Cover, Titel, Beschreibung, Rating).
  3. index.html bindet Banner, Grid, Footer per th:insert ein.
  4. Zusätzliche Endpoints GET /contact und GET /version.

Controller siehe §6.3 (komplett aus dem Lösungs-ZIP). Index-Template siehe §6.4. Grid-Fragment siehe §6.5.

Der Controller-Aufruf movieService.getAllMovies() liefert bereits List<MovieDTO> — das DTO enthält schon alle Felder, die das Template braucht (kein zusätzliches Mapping nötig).

🧠 Verständnis-Checks

Klick auf „Antwort anzeigen" — schnelles Selbstabfragen ohne Scrollen.

Was bedeuten ${…} · *{…} · @{…} · ~{…}?

Antwort anzeigen
${var} Variable/OGNL · *{feld} Selection (innerhalb th:object) · @{/url} URL (mit Context-Path) · ~{frag :: id} Fragment-Referenz.

th:insert vs th:replace?

Antwort anzeigen
th:insert packt das Fragment in den umschließenden Tag (Tag bleibt erhalten). th:replace ersetzt den Tag komplett durch das Fragment.

Wie iterierst du über eine Liste und nutzt den Iter-Status?

Antwort anzeigen
th:each="item, stat : ${items}" — stat bietet index, count, size, first, last, even, odd.

Wie definierst du ein wiederverwendbares Fragment banner und bindest es ein?

Antwort anzeigen
Definition: <section th:fragment="banner">…</section>. Einbinden: <section th:insert="~{fragments/banner :: banner}"></section>.

Wofür der Namespace xmlns:th="http://www.thymeleaf.org"?

Antwort anzeigen
Damit der Browser/Validator die th:-Attribute kennt. Templates bleiben so valides HTML — du kannst sie auch ohne Server öffnen, der Browser ignoriert die th:-Attribute einfach.

Wann gibst du im Controller String zurück, wann ModelAndView?

Antwort anzeigen
String reicht, wenn du nur den Template-Namen brauchst und Daten via Model-Parameter ergänzt. ModelAndView bündelt Template + Daten in einem Objekt — übersichtlicher, wenn man mehr als eine Variable hat.
