3.1 REST-Grundlagen & HTTP

REST (Representational State Transfer) ist ein Architekturstil für Web-APIs. Ressourcen werden über URIs adressiert; Operationen sind die HTTP-Methoden.

3.2 @RestController

@RestController = @Controller + @ResponseBody auf jeder Methode. Die Rückgabe wird automatisch zu JSON serialisiert (Jackson).

@RestController
@RequestMapping("/api/v1/awards")
public class AwardControllerImpl implements AwardController {

    private AwardService awardService;

    public AwardControllerImpl(AwardService awardService) {
        this.awardService = awardService;
    }

    @GetMapping
    public List<Award> getAllAwards() {
        return awardService.getAllAwards();
    }

    @GetMapping("/{awardId}")
    public Award getAwardById(@PathVariable("awardId") Long awardId) {
        return awardService.getAwardById(awardId);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Award addAward(@RequestBody Award award) {
        return awardService.addAward(award);
    }

    @PutMapping("/{awardId}")
    public Award updateAwardById(@PathVariable("awardId") Long awardId,
                                 @RequestBody Award award) {
        award.setId(awardId);
        return awardService.updateAward(award);
    }

    @DeleteMapping("/{awardId}")
    public void removeAwardById(@PathVariable("awardId") Long awardId) {
        awardService.removeAwardById(awardId);
    }
}

3.4 Status-Codes setzen

// per Annotation auf der Methode
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public Award addAward(@RequestBody Award award) { ... }

// per ResponseEntity (flexibler — Status & Header dynamisch)
@GetMapping("/{id}")
public ResponseEntity<Award> get(@PathVariable Long id) {
    Award a = awardService.getAwardById(id);
    if (a == null) return ResponseEntity.notFound().build();
    return ResponseEntity.ok(a);
}

3.5 DTOs & MapStruct

DTO (Data Transfer Object): eigene Klasse für die API-Sicht, getrennt von der Entity. Vorteile:

  • API-Stabilität: Entity-Refactor bricht den Contract nicht.
  • Versteckt sensitive Felder (Passwort-Hash, interne IDs).
  • Vermeidet Endlos-Loops bei Bidirektionalen Beziehungen während JSON-Serialisierung.
@Getter @Setter @NoArgsConstructor
public class AwardDTO {
    private Long id;
    private String academy;
    @NotBlank
    private String category;
    private int celebrationYear;     // umbenannt von "yearAwarded"!

    public AwardDTO(Long id, String academy, String category, int celebrationYear) {
        this.id = id;
        this.academy = academy;
        this.category = category;
        this.celebrationYear = celebrationYear;
    }
}

MapStruct — Mapper-Generierung

MapStruct generiert zur Compilezeit Mapper-Klassen aus einem Interface. componentModel = "spring" registriert die generierte Implementierung als Spring Bean (per @Component) — du kannst sie also einfach injizieren.

@Mapper(componentModel = "spring")
public interface AwardMapper {

    @Mapping(source = "yearAwarded", target = "celebrationYear")
    AwardDTO awardToAwardDTO(Award award);
    List<AwardDTO> awardsToAwardDTOs(List<Award> awards);

    @InheritInverseConfiguration
    @Mapping(target = "movie", ignore = true)
    Award awardDTOToAward(AwardDTO awardDTO);
    List<Award> awardDTOsToAwards(List<AwardDTO> awardDTOs);
}

@InheritInverseConfiguration dreht das oben definierte Mapping um — du musst die Field-Mappings nicht doppelt schreiben.

3.6 OpenAPI / Swagger

OpenAPI (früher Swagger) ist ein Standard, um REST-APIs maschinen­lesbar zu beschreiben. Die Bibliothek springdoc-openapi-ui generiert aus deinen @RestController-Klassen automatisch:

  • /v3/api-docs — JSON-Beschreibung
  • /swagger-ui.html — interaktive HTML-Doku zum Ausprobieren

Mit Annotationen wie @Operation(summary = "…"), @Parameter(description = "…"), @ApiResponse(responseCode = "404", description = "…") kannst du die Doku verfeinern.

⚙ Aufgabe 5 — DTO + Mapper

Aufgabenstellung

Trenne die API-Sicht von der Entity:

  1. Lege einen AwardDTO an. Das Feld yearAwarded aus der Entity soll im DTO celebrationYear heißen (Renaming-Mapping).
  2. Lege einen MapStruct-AwardMapper an, der zwischen Entity und DTO konvertiert (in beide Richtungen).
  3. Passe Service und Controller so an, dass sie nach außen DTOs liefern und entgegennehmen, intern aber Entities verwenden.
  4. Setze auf das DTO-Feld category die Validierung @NotBlank.

DTO + Mapper: siehe Codebeispiele unter §3.5.

Im AwardServiceImpl wird der Mapper injiziert und nach jedem Repository-Call angewendet:

@Service
public class AwardServiceImpl implements AwardService {

    private final AwardRepository repo;
    private final AwardMapper     mapper;

    public AwardServiceImpl(AwardRepository repo, AwardMapper mapper) {
        this.repo   = repo;
        this.mapper = mapper;
    }

    @Override
    public List<AwardDTO> getAllAwards() {
        return mapper.awardsToAwardDTOs(repo.findAll());
    }

    @Override
    public AwardDTO addAward(AwardDTO dto) {
        Award entity = mapper.awardDTOToAward(dto);
        return mapper.awardToAwardDTO(repo.save(entity));
    }
}

⚙ Bonus 1 — DirectorController CRUD + Sub-Resource

Aufgabenstellung

Baue analog zum AwardController einen DirectorController:

  1. Standard-CRUD über /api/v1/directors: GET-Liste, GET-by-ID, POST, PUT, DELETE.
  2. Sub-Resource: GET /api/v1/directors/{id}/movies liefert die Filmografie eines Directors.
  3. DTOs trennen: DirectorDTO (mit ID, Name, Geburtsjahr, Nationalität, List<Long> movieIds).
  4. POST gibt Status 201 zurück.
@RestController
@RequestMapping("/api/v1/directors")
public class DirectorControllerImpl implements DirectorController {

    private final DirectorService service;

    public DirectorControllerImpl(DirectorService service) {
        this.service = service;
    }

    @GetMapping
    public List<DirectorDTO> getAll() {
        return service.getAll();
    }

    @GetMapping("/{id}")
    public DirectorDTO getById(@PathVariable Long id) {
        return service.getById(id);
    }

    // Sub-Resource: Filmografie eines Directors
    @GetMapping("/{id}/movies")
    public List<MovieDTO> getMovies(@PathVariable Long id) {
        return service.getMoviesOfDirector(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public DirectorDTO add(@Valid @RequestBody DirectorDTO dto) {
        return service.add(dto);
    }

    @PutMapping("/{id}")
    public DirectorDTO update(@PathVariable Long id,
                              @Valid @RequestBody DirectorDTO dto) {
        dto.setId(id);
        return service.update(dto);
    }

    @DeleteMapping("/{id}")
    public void delete(@PathVariable Long id) { service.delete(id); }
}

Sub-Resource-Pattern: Wenn eine Ressource gehört zu einer anderen, wird sie als Pfadkomponente eingehängt: /parents/{id}/children. Saubere REST-Konvention statt /movies?directorId=5.

⚙ Bonus 2 — @Valid + Validation auf AwardDTO

Aufgabenstellung

Die Folien listen die Validierungs-Annotationen @NotBlank, @NotNull, @Size, @Pattern, @Min, @Max + @Valid. Erweitere den AwardDTO um vollständige Validierung:

  1. category: nicht blank, max. 60 Zeichen.
  2. academy: nicht null, max. 40 Zeichen.
  3. celebrationYear: zwischen 1900 und 2100.
  4. id: optional (darf null sein, wird beim POST gesetzt).
  5. Im Controller: @Valid vor @RequestBody — fehlerhafte Requests landen automatisch bei 400.
@Getter @Setter @NoArgsConstructor
public class AwardDTO {
    private Long id;

    @NotNull
    @Size(max = 40)
    private String academy;

    @NotBlank
    @Size(max = 60)
    private String category;

    @Min(1900)
    @Max(2100)
    private int celebrationYear;

    public AwardDTO(Long id, String academy, String category, int celebrationYear) {
        this.id = id;
        this.academy = academy;
        this.category = category;
        this.celebrationYear = celebrationYear;
    }
}

Im Controller — @Valid aktiviert die Prüfung:

@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public AwardDTO addAward(@Valid @RequestBody AwardDTO award) {
    return awardService.addAward(award);
}

@PutMapping("/{id}")
public AwardDTO updateAward(@PathVariable Long id,
                            @Valid @RequestBody AwardDTO award) {
    award.setId(id);
    return awardService.updateAward(award);
}

Wenn Spring eine Constraint-Violation entdeckt, beantwortet es den Request automatisch mit 400 Bad Request — der Service-Call passiert gar nicht. Das ist genau das Verhalten, das auch in Aufgabe 6 mit verify(service, never()).addMovie(any()) getestet wird.

🧠 Verständnis-Checks

Klick auf „Antwort anzeigen" — schnelles Selbstabfragen ohne Scrollen.

Welche HTTP-Methode für: Anlegen / Lesen / Komplett-Update / Teil-Update / Löschen?

Antwort anzeigen
POST (anlegen), GET (lesen), PUT (komplett-Update / Ersetzen), PATCH (Teil-Update), DELETE (löschen). PUT & DELETE sind idempotent, POST & PATCH nicht.

Status 200 vs 201 vs 204 — wann was?

Antwort anzeigen
200 OK: Erfolg mit Antwortbody (typisch GET, PUT). 201 Created: Ressource neu angelegt (POST). 204 No Content: Erfolg ohne Body (oft DELETE).

Status 400 vs 404 vs 401 vs 403?

Antwort anzeigen
400: Anfrage ungültig (Validierungsfehler, kaputtes JSON). 404: Ressource existiert nicht. 401: nicht eingeloggt. 403: eingeloggt, aber keine Berechtigung.

@PathVariable vs @RequestParam — wann was?

Antwort anzeigen
@PathVariable: Teil der URL (/awards/5) — identifiziert eine konkrete Ressource. @RequestParam: Query-String (/awards?year=2020) — Filter, Sortierung, Pagination.

Warum trennt man DTO von Entity?

Antwort anzeigen
API-Stabilität (Entity-Refactor bricht den Contract nicht), Verstecken sensitiver Felder (z.B. Passwort-Hash), und vermeiden von Endlos-Loops bei bidirektionalen Beziehungen während JSON-Serialisierung.

Was macht @InheritInverseConfiguration in MapStruct?

Antwort anzeigen
Spiegelt die im Forward-Mapping definierten @Mapping-Regeln automatisch um (z.B. celebrationYear → yearAwarded), sodass du das umgekehrte Mapping nicht doppelt schreiben musst.

Unterschied zwischen @ResponseStatus(HttpStatus.CREATED) und ResponseEntity.status(201).body(x)?

Antwort anzeigen
@ResponseStatus setzt den Status statisch pro Methode. ResponseEntity ist dynamisch — du kannst Status, Header und Body abhängig vom Ergebnis setzen (z.B. 200 vs 404 in derselben Methode).
