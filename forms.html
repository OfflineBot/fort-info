🎯 TL;DR — was du wirklich wissen musst

  • Form-Binding: th:object="${form}" + th:field="*{feld}" setzt id, name, value automatisch.
  • Validation: Annotationen am DTO (@NotBlank, @NotNull, @Size, @Min, @Max, @Pattern) + @Valid im Controller.
  • BindingResult muss direkt nach dem @Valid-Objekt im Methoden-Parameter stehen.
  • PRG-Pattern: nach erfolgreichem POST return "redirect:/path" — verhindert Doppel-Submit beim Refresh.
  • Conditionals: th:if für Anzeigen/Verstecken · Ternary ${cond ? 'x' : 'y'} für Werte/Klassen.
  • Fehler im Template: #fields.hasErrors('feld') + th:errors="*{feld}".

⚠ Typische Fehler / Klausur-Stolperfallen

Die Punkte, an denen die meisten in der Klausur Federn lassen.

⚠ BindingResult falsch positioniert
Muss direkt nach dem mit @Valid annotierten Objekt stehen. Andere Reihenfolge → Spring wirft MethodArgumentNotValidException + 400.
⚠ Validation greift nicht
@Valid auf dem Controller-Parameter vergessen → Constraints werden ignoriert. Außerdem auf der DTO-Klasse Felder mit @NotBlank etc. annotieren — sonst gibt es nichts zu validieren.
⚠ @NotBlank auf Nicht-String
@NotBlank funktioniert nur für String. Für Integer / Long: @NotNull. Für Collections: @NotEmpty. Verwechslung gibt Compile-Time-Fehler.
⚠ PRG-Pattern weglassen
Nach erfolgreichem POST direkt das Formular wieder rendern — Browser-Refresh wiederholt den POST (Doppel-Submit). Lösung: return "redirect:/path".
⚠ Ternary-Operator außerhalb ${…}
th:text="${age > 18} ? 'adult' : 'student'" — falsch. Korrekt: th:text="${(age > 18) ? 'adult' : 'student'}". Der Ternary muss innerhalb der Expression-Klammern stehen.

7.1 Formulare in Spring + Thymeleaf

Ein Formular hat in Spring drei Akteure:

  1. Eine Form-Klasse (DTO) mit den Feldern + Validierungs-Annotationen.
  2. Einen GET-Endpunkt, der das leere Form-Objekt ins Model legt und das Template rendert.
  3. Einen POST-Endpunkt, der das ausgefüllte Form mit @Valid entgegennimmt und entweder speichert (Redirect) oder bei Fehlern dasselbe Template erneut rendert.

7.2 th:object & th:field

Im Template aktiviert th:object die Selection-Expression *{…}, mit der du dann die Felder des Objekts referenzierst. th:field setzt automatisch id, name und value.

<form th:action="@{/awards}" th:object="${awardForm}" method="post">

  <div class="mb-3">
    <label class="form-label" for="academy">Academy</label>
    <input class="form-control" type="text" th:field="*{academy}">
  </div>

  <div class="mb-3">
    <label class="form-label" for="category">Kategorie</label>
    <input class="form-control" type="text" th:field="*{category}"
           th:classappend="${#fields.hasErrors('category')} ? 'is-invalid'">
    <div class="invalid-feedback" th:errors="*{category}"></div>
  </div>

  <div class="mb-3">
    <label class="form-label" for="celebrationYear">Jahr</label>
    <input class="form-control" type="number" th:field="*{celebrationYear}">
  </div>

  <button type="submit" class="btn btn-primary">Speichern</button>
</form>

7.3 Validation (@Valid)

Auf der Form-Klasse stehen Bean-Validation-Annotationen (Jakarta):

  • @NotNull — darf nicht null sein
  • @NotBlank — String, nicht null und nicht nur Whitespace
  • @NotEmpty — String/Collection, mind. ein Element
  • @Size(min=, max=) — Länge / Größe
  • @Min / @Max — Zahlenbereich
  • @Email — gültiges E-Mail-Format
  • @Pattern(regexp="…") — Regex
@Controller @RequestMapping("/awards")
public class AwardFormController {

    private final AwardService service;
    public AwardFormController(AwardService s) { this.service = s; }

    @GetMapping("/neu")
    public String form(Model model) {
        model.addAttribute("awardForm", new AwardDTO());
        return "awards/form";
    }

    @PostMapping
    public String save(@Valid @ModelAttribute("awardForm") AwardDTO form,
                       BindingResult br) {
        if (br.hasErrors()) return "awards/form";   // mit Fehlern zurück zum Formular
        service.addAward(form);
        return "redirect:/awards";                   // PRG-Pattern
    }
}

PRG-Pattern (Post-Redirect-Get): nach erfolgreichem POST redirect auf eine GET-Seite, damit ein Browser-Refresh nicht den POST wiederholt.

⚙ Weitere Aufgabe 1 — Movie-Edit-Form

Aufgabenstellung

Baue ein vollständiges Edit-Formular für einen Film:

  1. GET /movies/{id}/edit → Form mit aktuellen Werten vorbefüllt.
  2. POST /movies/{id} → Validation, dann save + redirect auf Detail-Seite.
  3. Validations: @NotBlank title, @Min(0) duration, @PastOrPresent premiereDate, @DecimalMax("10.0") @DecimalMin("0.0") imdbRating.
  4. Bei Validierungsfehlern: dasselbe Form-Template mit Fehlermeldungen anzeigen.
// DTO mit Validation:
@Getter @Setter
public class MovieFormDTO {
    private Long id;

    @NotBlank
    private String title;

    @Min(0)
    private double duration;

    @PastOrPresent
    private LocalDate premiereDate;

    @DecimalMin("0.0") @DecimalMax("10.0")
    private double imdbRating;
}

// Controller:
@Controller @RequestMapping("/movies")
public class MovieFormController {

    private final MovieService service;
    public MovieFormController(MovieService s) { service = s; }

    @GetMapping("/{id}/edit")
    public String editForm(@PathVariable Long id, Model model) {
        MovieDTO m = service.getMovieById(id);
        model.addAttribute("movieForm", toForm(m));
        return "movie/edit";
    }

    @PostMapping("/{id}")
    public String save(@PathVariable Long id,
                       @Valid @ModelAttribute("movieForm") MovieFormDTO form,
                       BindingResult br) {
        if (br.hasErrors()) return "movie/edit";
        form.setId(id);
        service.update(form);
        return "redirect:/movies/" + id;
    }
}
<form th:action="@{/movies/{id}(id=*{id})}" th:object="${movieForm}" method="post">
  <div class="mb-3">
    <label class="form-label">Titel</label>
    <input class="form-control" type="text" th:field="*{title}"
           th:classappend="${#fields.hasErrors('title')} ? 'is-invalid'">
    <div class="invalid-feedback" th:errors="*{title}"></div>
  </div>

  <div class="mb-3">
    <label class="form-label">IMDB-Rating</label>
    <input class="form-control" type="number" step="0.1" th:field="*{imdbRating}"
           th:classappend="${#fields.hasErrors('imdbRating')} ? 'is-invalid'">
    <div class="invalid-feedback" th:errors="*{imdbRating}"></div>
  </div>

  <button type="submit" class="btn btn-primary">Speichern</button>
</form>

⚙ Weitere Aufgabe 2 — Director-Form mit Custom Validation

Aufgabenstellung

Erstelle ein Form für einen Director mit eigener Validierungs-Annotation für die Nationalität (ISO-Ländercode 2 Großbuchstaben):

  1. DTO DirectorFormDTO mit Feldern name, geburtsjahr, nationality.
  2. Validations: @NotBlank name, @Min(1900) @Max(2025) geburtsjahr, @Pattern(regexp="[A-Z]{2}") nationality.
  3. Bei Fehler: Bootstrap-Feedback (rote Border + Fehlermeldung).
  4. Bonus: lokalisierte Fehlermeldung via messages.properties.
@Getter @Setter
public class DirectorFormDTO {
    @NotBlank(message = "{director.name.required}")
    private String name;

    @Min(value = 1900, message = "Vor 1900? Wirklich?")
    @Max(value = 2025, message = "Aus der Zukunft?")
    private int geburtsjahr;

    @Pattern(regexp = "[A-Z]{2}",
             message = "ISO-Ländercode (z.B. US, DE, GB)")
    private String nationality;
}

@Controller @RequestMapping("/directors")
public class DirectorFormController {

    @GetMapping("/neu")
    public String form(Model m) {
        m.addAttribute("directorForm", new DirectorFormDTO());
        return "director/form";
    }

    @PostMapping
    public String save(@Valid @ModelAttribute("directorForm") DirectorFormDTO form,
                       BindingResult br) {
        if (br.hasErrors()) return "director/form";
        directorService.create(form);
        return "redirect:/directors";
    }
}

messages.properties:

director.name.required=Bitte den Namen eingeben.

Lerneffekt: Validation-Messages können entweder hartcodiert in der Annotation oder via {key}-Referenz aus messages.properties geladen werden — letzteres ist i18n-fähig.

⚙ Weitere Aufgabe 3 — Ternary-Operator + th:classappend

Aufgabenstellung

Die Folien zeigen den Ternary-Operator (Bedingung ? Then : Else) explizit als Kurzschreibweise für If-Then-Else in Thymeleaf-Attributen. Setze ihn ein, um Conditionals knapp zu formulieren:

  1. Zeige in der Movie-Card das Rating mit Label „adult"/„kid" via th:text="${(movie.imdbRating > 8) ? 'TOP' : 'OK'}".
  2. Setze die CSS-Klasse einer Tabellenzeile abhängig vom Iter-Status via th:classappend.
  3. Style einen Award-Badge nach Jahrzehnt unterschiedlich.
  4. Erkläre, wann Ternary besser ist als th:if.
<!-- Beispiel 1: Text per Ternary -->
<span th:text="${(movie.imdbRating > 8) ? 'TOP' : 'OK'}">OK</span>

<!-- Beispiel 2: Klasse per th:classappend mit Iter-Status -->
<table>
  <tr th:each="m, stat : ${movies}"
      th:classappend="${stat.even} ? 'gerade' : 'ungerade'">
    <td th:text="${m.title}"></td>
  </tr>
</table>

<!-- Beispiel 3: Badge nach Jahrzehnt -->
<span th:text="${a.academy}"
      th:classappend="${a.celebrationYear >= 2020}
                       ? 'badge bg-success'
                       : 'badge bg-secondary'">
</span>

Ternary vs th:if:

  • th:if versteckt/zeigt das gesamte Element. Nutze es, wenn das Element ganz fehlen soll.
  • Ternary entscheidet nur den Wert innerhalb eines Attributs. Nutze es, wenn das Element immer da ist, aber Text/Klasse/Style variieren soll.

Folien-Hinweis: "Der Ternary-Operator wird innerhalb des Evaluationsbereichs ${…} geschrieben."

🧠 Verständnis-Checks

Klick auf „Antwort anzeigen" — schnelles Selbstabfragen ohne Scrollen.

@NotNull vs @NotBlank vs @NotEmpty — Unterschied?

Antwort anzeigen
@NotNull: Wert darf nicht null sein (leerer String wäre ok). @NotEmpty: für Strings/Collections — nicht null und nicht leer (whitespace ok). @NotBlank: nur Strings — nicht null, nicht leer, nicht nur Whitespace.

Was passiert, wenn ein Formular die @Valid-Constraints nicht erfüllt?

Antwort anzeigen
Die Validierung schlägt fehl, der Service wird nicht aufgerufen. BindingResult wird mit den Fehlern befüllt. Best Practice: dasselbe Form-Template wieder rendern, damit der User korrigieren kann.

Wo MUSS BindingResult in der Parameterliste stehen?

Antwort anzeigen
Direkt nach dem mit @Valid annotierten Objekt. Sonst sieht Spring die Bindung als unvollständig und wirft eine Exception.

Erkläre das PRG-Pattern.

Antwort anzeigen
Post-Redirect-Get: nach erfolgreichem POST gibst du redirect:/path zurück, damit der Browser per GET die nächste Seite holt. Vorteil: ein Refresh wiederholt nicht den POST und verhindert Doppel-Submit.

Wie zeigst du im Template einen Validierungsfehler für das Feld category an?

Antwort anzeigen
<p th:if="${#fields.hasErrors('category')}" th:errors="*{category}"></p>. Mit Bootstrap zusätzlich th:classappend="${#fields.hasErrors('category')} ? 'is-invalid'" auf dem Input.

Welche Spring-Annotation bindet das POST-Body-Form an dein DTO?

Antwort anzeigen
@ModelAttribute("name") FormDTO form — Spring liest die Form-Felder und mappt sie auf die DTO-Properties. Mit @Valid davor wird Bean Validation ausgeführt.
